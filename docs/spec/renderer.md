## 6. レンダラー実装（Vulkan Compute）

### 6.0 レイトレーシングか、パストレーシングか

本体は**測地線レイトレーシング（＋ボリュームのレイマーチング）**であり、パストレーシングではない。違いと、本設計での扱いは次の通り。

| | レイトレーシング（本設計の本体） | パストレーシング |
|---|---|---|
| 1ピクセルの計算 | カメラから光線を1本（＋サブピクセルで数本）決定的に辿る | 光の経路をランダムに多数サンプリングし、平均して収束させる（モンテカルロ法） |
| 表面での扱い | 交点で発光と直接光を決定的に評価する | 交点でランダムな方向に跳ね返し、その先の経路全体を再帰的に辿る |
| 得意なもの | 影、重力レンズ、フォトンリング、円盤の高次像、ドップラービーミング。本プロジェクトの画はほぼ全部これで決まる | 大域照明、柔らかい相互反射、ボリュームの多重散乱、コースティクス |
| 欠点・コスト | 相互反射や間接光は近似になる | ノイズが出て、収束に多数サンプルが要る。本プロジェクトでは跳ね返りのたびに測地線積分（数百〜数千ステップ）を最初からやり直すため、跳ね返し1回でコストが数倍になる |

採用方針は**ハイブリッド**である。

1. 主経路: 測地線レイトレーシングで決める（影、レンズ像、円盤の自己発光）
2. 二次経路として「直接光だけ」足す: 宇宙船などの表面の点から円盤の代表点へ向けて影用の測地線を飛ばし、円盤の光が届くか・どう曲がって届くかを評価する。これで「円盤の光に照らされる宇宙船」はパストレーシングなしで物理らしく描ける
3. パストレーシング化するのは最後の発展とする: 円盤ボリューム内の多重散乱や、物体同士の相互反射が画の不足になったと確認できてから、主経路の先に跳ね返し回数1回までの経路サンプリングを追加する。最初から全面パストレーシングにすると、計算量とノイズのせいで物理検証（§8）自体ができなくなる

なお本設計のプログレッシブ蓄積は、サブピクセルのジッターとボリュームのジッターを平均するためのもので、パストレーシングの経路サンプリングとは別物である。

### 6.1 パイプライン構成

| パイプライン | 入力 | 出力 | 備考 |
|---|---|---|---|
| Particle Update | 前フレームの粒子状態 SSBO | 粒子状態 SSBO、空間グリッド | 動画用。静止画では初期配置のみ |
| Geodesic Trace | 蓄積バッファ、シーン、粒子グリッド、星空 | 蓄積バッファへ加算 | 本体。1ピクセル = 1スレッド |
| Lens Simulation | リニア HDR 画像、レンズプリセット、高輝度源リスト | フレアを加算した HDR 画像 | §6.7。CAPCOM RE:2023 の物理ベース手法に倣う |
| Film Emulation | フレア済み HDR | フィルム特性を加えた HDR | §6.8。ハレーション、グレイン等 |
| Resolve | 蓄積バッファ | EXR / PNG | 平均化とトーンマップ。クリーンな HDR EXR も常時併せて出す |

プログレッシブレンダリングにする: 1パスで全ステップを終わらせるのではなく、サンプルを分けて蓄積し、プレビューでは早期に粗い画が見えるようにする。

### 6.2 1ピクセルの処理（疑似コード）

```
状態 = カメラから初期条件を作る()
色 = 0, 透過率 = 1
for step in 0..MAX_STEP:
    if r < 地平面+ε: break              // 落下。残りは黒
    if r > 逃散半径: 色 += 透過率 * 星空(方向); break
    if 赤道面を跨いだ:
        if r が円盤範囲内: 色 += 透過率 * 円盤の発光(g補正つき); 透過率 *= 円盤の不透明度
    if 円盤の厚みの内側: 色, 透過率 = ボリュームを1ステップ分積分()
    if 主役メッシュの近傍: セグメント交差判定()  // §6.4
    RK4で1ステップ進める(適応ステップ幅)
出力: 色
```

### 6.4 主役メッシュ（Blender の物体）の扱い

曲がった光線との交差は、測地線を短い直線セグメント列とみなし、セグメントごとに BVH でレイ・トライアングル交差を行う。

- セグメント長はステップ幅と連動させる。ブラックホール近傍では短く、遠方では長く
- メッシュのマテリアルは単純なものだけ対応する: 発光、拡散（近似）、鏡面（反射方向も測地線で追うと高コストなので、遠方近似で直線反射）
- ブラックホールから遠い物体は重力の影響が小さいので、そもそも通常の直線レイトレーシングで描いて合成する方が速くて正確、という割り切りも選べる。設計としては両対応にしておき、物体ごとにフラグで選ぶ

### 6.5 他の物体（宇宙船など）の重力による移動は実装するか

結論: **「光が受ける重力」は実装する。「物体の運動」は2モード用意する。「物体が時空を曲げること」は実装しない。**

1. **光への影響（実装する）**: 宇宙船から出た・反射した光も測地線に従う。つまり宇宙船の像もレンズで歪み、ブラックホールの近くでは位置がずれて見える。これは §6.4 のセグメント交差で自然に入る
2. **物体の運動への影響（モードで選ぶ）**:
   - モードA「キーフレーム（既定）」: 位置は Blender のアニメーションが決める。演出上の意図が優先される場面はこちら。レンダラーはその時刻の位置に置くだけで、運動の物理計算はしない
   - モードB「弾道（測地線）」: 初期位置と初速度だけを渡し、§3.2 の積分器を $H = -1/2$ で回して軌道を計算する。パーティクル（§5）と全く同じ仕組みで、対象が1個増えるだけなので実装は軽い。自由落下・周回・歳差が正しく出る。ただし推力（エンジン噴射）がある運動は測地線ではないので、その場合はモードAに戻すか、固有加速度を外力として足す拡張が要る
3. **物体が時空を曲げること（実装しない）**: 宇宙船や円盤の質量がブラックホールの時空を変える効果（反作用）、物体同士の重力、ブラックホール自体が引っ張られて動くことは扱わない。時空は固定した Kerr 計量とし、物体はその上を動くテスト粒子とする。宇宙船の質量はブラックホールに対して無視できるため、これは物理的に正しい近似である。例外は「もう1つブラックホールや中性子星がある」場合で、そのときは計量自体が別物になるため本設計の対象外とする

### 6.6 性能の見通し（概算）

- 1920×1080 = 約 207 万ピクセル
- 1ピクセルあたり平均 300〜1500 ステップ（適応幅あり。画面の大部分はブラックホールから遠く、ステップは大きく取れる）
- 単純計算で $10^9$ オーダーの RK4 ステップ。本番1枚で数分〜数十分は普通に想定する。だからこそプログレッシブ表示とプレビュー解像度（480p、ステップ上限を落とす）が必須
- 精度を落とさず速くする余地: 画面をタイル分割し、ブラックホール近傍のタイルだけステップを細かくする / 数値微分を解析微分に替える / 保存量を使って $\theta$ 運動を分離する

### 6.7 カメラ内部のシミュレーション: レンズフレア（物理ベース）

目標は「IMAX のフィルムカメラで現地で撮ってきた」映像である。そのためフレアはスプライトを貼る演出ではなく、CAPCOM オープンカンファレンス プロフェッショナル RE:2023「Ray Tracing Lens Flare」で紹介された物理ベース手法に倣い、**カメラのレンズ群の中でもう一度レイトレーシングする**ことで作る。レンズフレア資料: https://www.docswell.com/s/CAPCOM_RandD/KYWLRL-RE2023/1

処理の位置づけが重要である。時空を辿る測地線計算は「レンズ前玉に光が届くまで」で終わり、レンズ内部からセンサ（フィルム面）までは通常の直線光学で計算する。2つのレイトレーサーは HDR 画像を介して直列につながる。

```
測地線レンダー → リニアHDR (EXR) → レンズシミュレーション → フィルム特性 → トーンマップ
```

CAPCOM 手法から採用する要素:

1. **レンズデータの表現**: レンズ群の各表面を平面／球面の列として持つ。プリセット（レンズ処方）は「曲率半径、次の表面までの距離、ガラスの屈折率と分散（Sellmeier 係数または $n_d$ とアッベ数）、口径、コーティング膜厚」を並べた JSON とする。実在レンズの処方は特許文献に公開例があるので、それを初期プリセットにする。IMAX 用レンズの処方は非公開のため「IMAX 専用レンズそのもの」ではなく「大判シネレンズ相当の処方」を目指す、と線を引く
2. **ゴースト**: 前玉に等間隔グリッド光線を入射させ、レンズ内を追跡する。ゴーストは表面で**ちょうど2回反射**する経路だけを数える（反射率が小さいため。表面 $n$ 枚なら ${}_nC_2$ 通り）。センサ面で歪んだグリッドがそのままゴーストの変形になる。明るさは、(a) フレネル反射率、(b) 反射防止膜の薄膜干渉による波長依存の反射率（MgF2 単層膜モデル。これがゴーストの色の主因）、(c) グリッドセルの面積変化から求める集光度（コースティック的な明暗）
3. **スターバースト**: 絞り羽根マスク画像のフーリエ変換による Fraunhofer 回折で作る。絞り羽根の枚数と F 値で形が変わる。前玉のゴミ・傷テクスチャをマスクに乗算すると回折像が実際に汚れる（資料の手法そのまま）
4. **ゴースト像の回折伝搬**: ゴーストにマッピングする像は帯域制限角スペクトル法（Band-Limited Angular Spectrum）で伝搬計算する。通常の角スペクトル法で出るエイリアシングノイズを避けるための選択
5. **波長の扱い**: 可視域から約9波長を標本する。本プロジェクトには有利な点がある。円盤の放射は温度と $g$ から決まる黒体スペクトルなので（§4.3、§4.4）、RGB からスペクトルを「捏造」するのではなく、放射点では原理的に正しいスペクトルが知れている。フレア段では HDR 画像の RGB を黒体近似でスペクトルに復元して使う

本プロジェクト固有の適応（CAPCOM の前提と違う点）:

- **光源が点ではなく面（円盤）である**: CAPCOM の想定は画面内外の光源方向が主だが、こちらで一番明るいのは広がった円盤像である。対策として、測地線パスの出力に「高輝度源リスト」（閾値を超えたピクセルのクラスタ: 画面座標、スペクトル、強度）を併せて出し、ゴースト計算の入射光はこのリストからサンプルする。円盤の高次像も別々の源として現れるのが正しい
- **画面外の光源**: 円盤は画角の外にも広がり得て、その光でもフレアは出る。シャドウマップは使えないので、代わりに本番画角より広く（例: 1.25 倍の FOV で）レンダーしたオーバースキャン HDR をフレア段の入力にし、最後に本番画角で切り出す
- **遮蔽**: 宇宙船などで円盤が隠れている場合、その情報はレンダー済み HDR に既に含まれているため追加の遮蔽判定は不要（画面外分はオーバースキャンが担う）

フレア段のコストは測地線段に比べて無視できる水準である（CAPCOM の実測でもリアルタイムのミリ秒級。本プロジェクトはグリッドを 64×64、波長数を増やすなど、オフライン向けに重くしてよい）。

### 6.8 フィルム特性（IMAX フィルムらしさ）

レンズフレアだけでは「フィルムカメラで撮った」感じにはならない。以下を Lens Simulation の後段に、すべて任意 ON/OFF 可能な段として置く。

- **ハレーション**: 強い光がフィルム乳剤内で散乱して光源の周りに赤橙色の halo が出るフィルム特有の現象。高輝度部分を抽出してぼかし、赤寄りの色で加算する。円盤の最内縁が一番明るい本プロジェクトでは特に効く
- **グレイン（粒状性）**: 輝度依存のノイズをフレームごとにシードを変えて加える。動画で静止ノイズにならないこと
- **ゲートウィーブ**: 動画時のみ。フィルム搬送の微小な揺れとして、フレーム全体にサブピクセル級のランダムな平行移動を与える（既定は OFF。やり過ぎると安っぽくなる）
- **周辺減光と柔らかさ**: レンズプリセット側の特性として扱い、フレア段と一緒に計算する。シャープネス一辺倒にしない

出力は「クリーンなリニア HDR EXR（フレア・フィルム特性なし）」と「仕上げ済み」の両方を常時出す。物理検証（§8）はクリーン版で行うためである。

### 6.9 解像度とスケールの仕様（FHD 既定、柔軟に変更可能）

解像度は固定値としてコードに埋め込まない。すべて scene.json のパラメータとし、内部解像度は係数で派生させる。

| パラメータ | 既定 | 備考 |
|---|---|---|
| 出力幅 × 高さ | 1920 × 1080 (FHD) | 720p / 4K UHD / 任意値を指定可能。測地線段のコストはピクセル数にほぼ比例 |
| ゲート（画角の基準） | 任意のセンサ幅・高さ (mm) | プリセット: IMAX 15/70（70.41 × 52.63 mm、アスペクト約 1.34）、65mm、Super 35、フルサイズ。FHD 出力でもアスペクトはゲートと画角で決まり、16:9 に固定しない |
| 内部レンダースケール | 1.0 | 2.0 でスーパーサンプリング（アンチエイリアス兼用） |
| オーバースキャン倍率 | 1.25 | フレア段用（§6.7）。不要なら 1.0 |
| フレア内部解像度スケール | 0.5 | CAPCOM 実装は 1/4 解像度。画質を見て調整 |
| 波長サンプル数 | 9 | フレア段のスペクトル標本数 |

なお IMAX 画質そのもの（解像感）を FHD で再現することは目的にしない。狙うのは解像度ではなく、レンズとフィルムを通した光の振る舞いである。
