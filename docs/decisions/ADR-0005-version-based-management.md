# ADR-0005: 開発管理の単位を Phase からバージョンへ切り替える

- 状態: 承認済み (2026-10-27)

## 背景

当初は仕様書の Phase (1〜5、4.5) をそのまま GitHub の Milestone と
ラベルにして管理していた。しかし Phase は技術的な依存関係の区分であり、
1つの Phase が数か月単位の大きさになること、Phase 同士が実際には
並行し得る (例: レンズ段は円盤の物理と独立に着手できる) ことから、
日々の開発管理の単位としては粗い。

## 決定

- 開発管理の単位はバージョン (セマンティック バージョニング) とする。
  GitHub の Milestone はバージョン名にし、Issue は目標バージョンの
  Milestone に紐づける。タグと GitHub Release もバージョン単位で切る
- Phase は仕様書 (docs/spec) 上の技術区分として残す。ロードマップの
  章立てと完了条件は Phase で書き、管理 (Milestone / Issue) は
  バージョンで行う。対応表は
  docs/spec/verification-and-roadmap.md の冒頭に置く
- バージョンとラベルの二重管理を避けるため、phase-* ラベルは廃止する。
  バージョンの紐づけは Milestone のみで行う

## バージョン計画

| バージョン | 内容 | 対応する Phase |
|---|---|---|
| v0.1.0 | 最初の像 (Vulkan 土台、測地線、カメラ、星空、薄い円盤) | Phase 1 |
| v0.2.0 | 円盤の物理 | Phase 2 |
| v0.3.0 | ボリュームとパーティクル | Phase 3 |
| v0.4.0 | Blender 連携 | Phase 4 |
| v0.5.0 | レンズ/フィルム段 | Phase 4.5 |
| v0.6.0 | Kerr 化 | Phase 5 |
| v1.0.0 | 統合と仕上げ (初の正式リリース) | 全体 |

1.0 未満では、各バージョンは「動く状態で出せる最小の前進」を単位とし、
互換性は保証しない。パッチバージョン (v0.1.1 等) は不具合修正のみ。
